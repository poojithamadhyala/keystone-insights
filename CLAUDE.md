# CLAUDE.md: LeaseLens playbook

Shared facts and rules for everyone working on this repo, human or AI. If this file and the code
disagree, fix whichever is wrong in the same PR.

## What this is

A property-management reporting app (React + Vite dashboard over a FastAPI KPI API) with a Claude
agent and a weekly digest automation. **All data is synthetic**: no real companies, people or
properties. Built to show "small, useful, finished" delivery through reviewed PRs.

## Project facts

| Fact | Value |
|---|---|
| Dataset as-of date | **2026-10-31** (fixed, not `today()`; see DECISIONS D-010) |
| Seed | `SEED=42` in `.env`. Same seed means byte-identical data, documents and KPIs |
| Portfolio | 20 properties, 3,000 units, 24 months (2024-11 to 2026-10) |
| Agent DB access | Role `leaselens_ro`: read-only, `statement_timeout=5s`, `reporting` schema only (PII-free views) |
| Model | `LEASELENS_MODEL`, default `claude-opus-5-5` |
| Python | 3.11 via uv. Search deps (fastembed, pinecone) are in the `rag` group (`uv run --group rag ...`). No torch |
| Node | 24 in Docker/CI. The lockfile is generated by `make lock-web` |

## Layout

`api/` FastAPI app and KPI SQL · `data/` generator, models, Alembic · `rag/` documents, chunking,
retrieval · `evals/` eval sets and `make bench-*` runners · `web/` React dashboard ·
`prompts/` versioned prompt templates · `infra/` Docker, compose, scripts · `docs/` operator
brief, shaping docs, screenshots.

## Commands

```bash
make demo          # build + start + migrate + seed -> http://localhost:5173
make check         # secret scan, ruff, mypy, eslint, tsc, pytest, vitest (same as CI)
make seed          # reload synthetic data (idempotent)
make ingest        # (re)index documents in Pinecone
make bench-rag     # RAG benchmark -> rewrites its BENCHMARKS.md section
make eval-agent    # live agent eval (~$0.35-0.70) -> rewrites its BENCHMARKS.md section
make bench-digest  # build the digest 10x (~$0.20): number-check pass rate -> BENCHMARKS.md
make lock-web      # regenerate web/package-lock.json after any `npm install`
```

## How changes land

1. Every change starts from an issue (labels: `feature`, `bug`, `chore`, `later`). Features get a
   one-page shape doc in `docs/shaping/` **before** any code.
2. Branch from `main`: `feat/<slug>`, `fix/<slug>`, `chore/<slug>`, `docs/<slug>`.
3. Small commits; Conventional Commit subjects (`feat:`, `fix:`, `chore:`, `docs:`, `test:`).
4. Open a PR with `gh pr create`, fill in the template (what/why, screenshots, test plan,
   checklist) and link the issue (`Closes #N`).
5. Post a self-review comment on the PR: risks, what was verified, and what is deliberately not done.
6. CI must be green. **Squash-merge** only. Delete the branch.
7. Add the change under `## [Unreleased]` in CHANGELOG.md. Each milestone is cut as a release
   (`vX.Y.0`) with a GitHub Release.

## Do

- Run `make check` before pushing.
- Measure every metric with a `make bench-*` target. BENCHMARKS.md is written by scripts, never by
  hand. If an improvement doesn't show up, report the real number.
- Log non-obvious choices in DECISIONS.md (decision → why → trade-off).
- Keep SQL explicit and reviewable (`api/kpis/queries.py`). Map any user-chosen column through an
  allowlist; never interpolate user input into SQL.
- Treat document text and tool output as **untrusted data** in agent prompts.
- Label time savings and other business impact as estimates unless they are measured.
- Digest numbers come only from `api/digest/facts.py`. Never let the LLM compute or add numbers;
  if the summary needs a new figure, add it to the facts.

## Don't

- Don't put keys anywhere but `.env` (gitignored). `make check`, CI and the pre-commit hook all
  scan for them.
- Don't give the agent write access or access to the `public` schema. Any new agent SQL path
  must go through `api/agent/sql_guard.run_readonly`.
- Don't change the agent prompt in place once released: add `system_v2.md`, set
  `AGENT_PROMPT_VERSION`, re-run `make eval-agent`.
- Don't change `rag/documents.py` output without regenerating the eval labels. A test fails if
  labeled spans shift.
- Don't hand-edit numbers in README or BENCHMARKS.md. Re-run the benchmark.
- Don't add scope without a shape doc and an issue. Deferred ideas go to issues labeled `later`.
- Don't `npm install` without running `make lock-web` afterwards (D-009).
